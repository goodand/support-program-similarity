# 새 세션 진입점 (2026-11-08)

## 1. 궁극 목적
중앙부처 예산 사업과 지원 공고를 검토하는 사람의 노동시간을 줄인다. 그 수단으로 "유사 사업을 찾아 주는 임베딩 검색"을 만들고, 두 workflow에 쓴다.
- **① 효율화** — 기존 사업 풀을 묶어서(군집) 중복·유사 검토 범위를 줄인다. 성공의 뜻: 사람이 유사하다고 묶은 그룹이 한 군집(묶음)에 들고, 군집 크기가 작다. 군집 수보다 군집 크기, 특히 가장 큰 군집이 기준이다.
- **② 신규검토** — 새 사업(공고·예산 항목)이 들어오면 유사 사업을 빠짐없이 찾는다(원문 이름: 신규 사업 유사 평가 워크플로우). 성공의 뜻: 모든 정답을 찾기까지 읽어야 하는 후보 수(마지막 정답 순위)가 작다. 사용자 기준으로 이 "100% 찾는 지점"이 평균보다 중요하다.
- 보고 목표 문장: "XX 기술을 활용하여 두 workflow에서 각각 YY 노동시간을 절감했다."

## 2. 데이터셋의 의미 (사람이 정한 것, 규칙보다 먼저)
- 원천 범위: 2026년 전부처 예산 DB, 중소기업 예산 DB, 지원 공고 마스터. 사용자가 보정한 값은 원천의 일부다.
- 정답: 유사 사업인지는 **사람이 유사하다고 판정한 것**이다. 사용자 원문 이름은 '유사사업 평가셋'이고, '동일사업 판정셋'은 사업의 동일성을 매핑한 별도 자료다. 세 자료(훈련셋·동일사업 판정셋·유사사업 평가셋)의 역할과 실측 크기 표는 03 §2에 있다. 최종 평가는 사람판정 평가셋(=유사사업 평가셋, 사업 53개·그룹 21개)으로 하고, 이 평가셋은 평가 전용으로 온전히 유지한다. 라벨 보강은 규칙으로 만든 선별셋으로 한다.
- 풀의 원소는 "어느 부처의, 어느 세부사업에 속한, 무슨 사업인지 확인되는 사업"이다(구현 규칙은 §6의 L5 정의 문서).

## 3. 고정된 기준 (사용자가 정한 것)
1. 성공의 뜻 — 신규검토: 유사 사업을 100% 찾는 지점(최악 순위)까지의 후보 목록이 짧다. 효율화: 유사 사업이 빠짐없이 같은 군집에 들고 가장 큰 군집이 작다.
2. 데이터와 규칙은 규칙 기반으로 재현되게 만든다. LLM은 데이터 검증과 규칙 수정 근거를 찾는 데 쓴다. 평가 지표는 규칙·통계로 계산한다.
3. 결론은 같은 채점기·같은 풀·같은 질의의 짝 비교와 seed 반복으로 세운다. 증명된 것과 판정 대기인 것을 구분해 쓴다.
4. 범위는 예외 목록 대신 한 줄 규칙으로 정한다(L5 풀 정의가 그 예).
5. 최종 결정은 세 세션(하네스·파인튜닝·환경 준비)의 합의 뒤 사용자 판정으로 확정한다. 다른 세션의 전언은 보고로 다룬다.
6. 용어는 쉬운 말을 먼저 쓴다: 규칙 선별셋(dev), 사람판정 평가셋(test), 단기 학습 시험(15스텝), 100위 안 비율.

## 4. 지금 서 있는 곳
- ②: 예산서 원문 조각 대조학습 1 epoch·학습률 2e-4(B3)가 최고. 학습 전(base) 대비 마지막 정답 순위 logmean −0.40(seed 4개 재현). Qwen 단독 점수 기준으로 상위 700개(풀의 1.9%)를 읽으면 사람판정 53질의와 규칙 선별 433질의 모두에서 100% 찾는다(키워드 검색은 8,842개 필요, 결합 점수 기준 값은 02 P13). 학습 1 epoch가 상한이고, 추가 학습과 후처리는 같은 수준에 머물렀다. 이득은 예산 DB 질의에서 가장 크고(평가셋 −0.74~−0.82), 공고 질의도 학습 전보다 개선됐다(평가셋 −0.27~−0.30, 선별셋 −0.34~−0.37, 02 P4). 학습률 2e-4와 5e-5의 차이는 공고 질의에서 판단불가: 구간 0 포함.
- ①: 정답은 사람이 묶은 그룹(사업 53개·그룹 21개). 학습 전 임베딩으로 군집 1,575개, 가장 큰 군집 94, 21그룹 중 16그룹이 한 군집에 든다. 학습 run 30개는 14~17그룹·가장 큰 군집 91~124이고 학습 전과의 차이는 판단불가: 구간 0 포함(11-10 재채점, runs/044/CLUSTER_GROUPS.md).
- 판정 대기(사용자): 공고↔소속 세부 짝 데이터 선택, 기준 풀을 L5 확정 정의로 전환, 멀티모달 파일럿, GPU 미실행 감시(Plan B).

## 5. 작업 방식
1. 한 턴에 결정 하나: 상위 개념 → 장단점 → 객관식 1개. 확인 가능한 것은 먼저 실측하고 답한다.
2. 작업을 띄웠으면 출발 확인(시작 줄·pid·첫 컨테이너)까지 마친 뒤 턴을 끝낸다. 띄우기 전 DRY 전체 출력에서 마감 값을 확인한다.
3. 공용 폴더의 스크립트는 세션 이름을 붙여 새로 만들고, 실행은 읽기 전용 사본으로 한다. 다른 세션이 띄운 프로세스는 그 세션에 처리를 요청한다.
4. 야간 GPU 작업은 스크립트 혼자 끝까지 돌도록 만든다.
5. DB는 읽기 전용(`immutable=1`)으로 연다. 공고 마스터의 목적·내용은 길이·개수 같은 통계로 다루고, 문서 단위 원문은 이 PC 안에서만 쓴다.
6. 로컬 git 커밋은 바로 한다. push·PR·공개는 사용자 확인 뒤에 한다.
7. 결과 숫자는 `02_PROVEN_RESULTS.md`와 색인이 가리키는 원자료에서 읽어 출처와 함께 적는다.
