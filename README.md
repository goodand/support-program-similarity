# Support Program Similarity

지원사업별로 준비된 본문을 비교하는 실행·평가 코드입니다. 현재 채택 구성은 **GPT-6.1-Sol / low**이며, 질의와 후보 본문으로 질의별 상위 30개 순위와 상위 5개 후보의 원문 인용 근거를 생성합니다. 확인한 정방향 평가 범위의 최대 표본에서 저장된 두 실행의 결과를 재계산해 선정했습니다. 기존 **Qwen3-Embedding-8B + Qwen3-Reranker-0.6B** 로컬 검색 코드도 역사적 기준선으로 유지합니다.

## 문서 파싱 MCP의 사용과 입력 생성

문서 준비·검수에는 [document-parser-mcp](https://github.com/goodand/document-parser-mcp)와 관련 파서 기능을 사용했습니다. 파서의 역할은 HWP·HWPX·PDF에서 텍스트와 문단·표·셀 구조, 원문 위치 및 시각 검수 근거를 확보하는 것입니다. 사업별 본문을 구성하는 전처리와 유사도 계산은 그 다음 단계입니다.

실제 평가 입력 생성 기록에서는 다음 경로를 확인할 수 있습니다.

- **기존 예산서 입력**: 준비 스크립트가 `govparse.native_toc`의 HWP/HWPX 읽기·문단 분류 함수를 직접 호출했습니다. 원본 해시와 문단 앵커(`section`, `ordinal`, `paragraph_header_rec`)를 보존하고, 후속 구획 코드가 사업별 문단을 선택했습니다. `field_leaf_v3` 입력은 기존 청크와 항목별로 선택한 문단을 합치되 `(source, paragraph_index)`로 중복을 제거해 만들었습니다.
- **추가 의견서 입력**: `pyhwp` 추출 결과의 표 번호·행·열과 원문 해시를 근거로 사업 개요 셀을 연결했습니다. 연결된 개요 셀의 동일 텍스트를 제거한 뒤 질의 본문으로 합쳤습니다. 대응 후보는 보충 공고 본문 또는 기존 사업 청크에서 가져왔습니다.
- **검색·평가 연결**: 이렇게 만든 사업별 본문을 `id`, `role`, `text`가 있는 입력 JSON으로 전달합니다. 사람이 검토한 유사성 판정과 판정 인용은 별도 평가 자료로 관리하며, 판정 인용을 사업 설명 대신 입력하지 않았습니다.

MCP는 문서 파싱·근거 조회를 위한 도구 인터페이스이며, 배치 입력 생성에는 파서 Python 함수를 직접 호출한 경로도 있습니다. **현재 공개된 검색 실행 코드는 입력 JSON을 읽고 MCP 서버를 직접 호출하지 않습니다.** 파서 설치만으로 사업 구획·입력 생성까지 자동 완료되는 구성은 아닙니다. 설치·MCP 등록은 [파서 README](https://github.com/goodand/document-parser-mcp#readme)를 참고하세요.

일부 사업과 문서의 연결에는 수동 출처 레지스트리와 상위사업 대체 입력이 포함되어 있습니다. 모든 입력 연결이 일반화된 자동 규칙으로 검증된 것은 아닙니다. 또한 기존 입력을 파서 저장소의 최신 버전으로 전부 재생성한 상태도 아닙니다. 재현 시 파서 버전, 원본·산출물 해시, 사업별 문단 선택·연결 기록을 함께 보존해야 합니다. 실제 원문과 평가 자료는 공개하지 않습니다.

## 선정 기준과 검증 범위

2026-10-20에 연결된 프로젝트의 완료된 실험 계열을 확인했습니다. 같은 정방향 질의·후보·알려진 정답을 사용하는 비교에서 최대 표본은 **질의 13개, 후보 140개, 알려진 정답 관계 19개**입니다. 7개 질의·140개 후보·9개 관계의 검토 표본은 이 통합 표본의 부분집합입니다. 통합 모델 비교뿐 아니라 정규화·내적·순위 결합, 윈도 점수, 부록 제거, 목적·내용·수혜대상 추출, 기존 참조를 포함한 청킹 비교 27개 결과 항목, 후속 검색 학습·구조화 추출·온톨로지 계열의 연결된 결과까지 대조했습니다. 이 범위가 PC 전체의 모든 무관한 실험을 전수 확인했다는 뜻은 아닙니다.

최대의 비교 가능한 완료 표본을 먼저 정하고, 같은 표본 안에서 모든 알려진 정답을 회수하는 데 필요한 최대 순위 `K_all`을 우선 비교한 뒤 MAP와 반복·전이 근거를 함께 검토했습니다. **GPT-6.1-Sol / low의 두 반복 모두 K_all과 MAP에서 기존 Qwen 채택 구성을 앞섰으므로 현재 선정과 기본 실행 코드를 변경했습니다.** 과거 Qwen의 전이 개선 이력은 역사적 근거로 보존합니다.

### 동일 입력의 두 반복과 비교 결과

Jina의 MRR은 이 집계 표에서 별도로 확인하지 않아 표시하지 않았습니다. 저장 집계에서 확인한 RRF60과 상위 10개 유지 보완 구성은 모두 K_all=18, Recall@20·30=1.0이었습니다. GPT low의 두 반복은 이보다 작은 K_all을 기록했습니다.

**이번에 순위로부터 지표를 재계산한 것은 GPT low 두 실행과 기존 Qwen 기준선입니다.** 나머지 행은 저장 집계와의 대조 결과입니다. 전체 정밀도 수치와 검증 방식, 원형 파일의 해시는 [선정 기록](release/selection.json)에 있습니다. Gemma 31B 결과는 원문 인용 검증을 통과하지 못해 채택 대상에서 제외했습니다.

### 재검증에서 확인한 내용과 한계

두 GPT low 실행의 최초 요청은 프롬프트·모델·reasoning 설정·출력 스키마가 같았습니다. 입력 대조에서 **153개 원문과 이름, 13개 질의의 제외 집합**이 일치했습니다. 원형 실험에 동결된 질의·후보 순서로 입력 행을 배치했을 때 공개 코드가 만든 입력·프롬프트·스키마는 실제 최초 요청과 같았고, 저장된 두 최종 출력도 공개 검증기를 통과했습니다. 실제 최초 요청에는 허용된 과제 입력만 포함되었고 도구와 이전 응답 연결은 없었습니다. 저장된 최종 출력의 **원문 인용 260개**를 다시 확인했습니다. 두 번째 실행은 인용 필드 한 곳을 수정한 결과이며, 그 수정 전후 순위와 나머지 필드는 같았습니다. **이번 갱신에서는 새 모델 서비스 요청이나 GPU 추론을 실행하지 않았습니다.**

인용이 원문에 존재하고 출력 구조가 맞는다는 검사는 유사성 판단의 의미적 정확성이나 정답의 완전성을 증명하지 않습니다. 두 반복은 같은 개발 자료를 재사용했습니다. 19개 질의·152개 고유 후보 원문을 사용한 역방향 실험도 같은 19개 관계를 재사용하고 후보 풀이 다르므로 현재 정방향 표본과 합산하지 않습니다. 기존 Qwen의 별도 10개 역방향 질의 시험 역시 문서·정답을 재사용한 전이 근거입니다. **독립적으로 보류한 미사용 사업에 대한 일반화 검증은 없습니다.**

558개 원천 파일의 자료 감사와 184개 구조화 관계의 라벨 준비 기록은 모델 평가 질의 수가 아닙니다. 해당 라벨 준비 기록에서 입력까지 연결되어 준비된 행은 0개였습니다. 원본 파싱·사업별 입력 연결의 수동 처리와 상위사업 대체 입력 한계도 그대로 남아 있습니다. 더 큰 독립 평가 표본과 완전한 정답 집합에서의 최고 성능을 보장하지 않습니다.

## 실행

Python 3.10 이상. 준비된 입력은 아래 형식의 JSON 목록입니다. `id`는 전체에서 고유해야 하며, `name`은 선택 항목입니다. `excluded_candidate_ids`는 질의에만 지정하는 선택 항목입니다. 중복 ID는 오류로 처리합니다. 동일 원문의 후보와 명시적으로 지정한 제외 후보를 제외합니다. 다음은 형식만 보여 주는 합성 예시이며, 기본 상위 30개 실행에는 각 질의마다 제외 후 후보가 최소 30개 필요합니다.

```json
[
  {"id":"Q1","role":"query","name":"합성 질의","text":"질의 사업 본문","excluded_candidate_ids":[]},
  {"id":"C1","role":"candidate","name":"합성 후보","text":"후보 사업 본문"}
]
```

### 채택 구성: GPT-6.1-Sol / low

설치되어 있고 기존 ChatGPT 계정으로 로그인한 Codex CLI가 필요합니다. CLI 설치·비대화형 사용은 [공식 문서](https://learn.chatgpt.com/docs/non-interactive-mode)를 참고하세요. 이 실행 경로는 원형 실험의 로컬 loopback 전송 방식을 사용해 Codex CLI의 기존 인증을 재사용합니다. 모델 지원은 해당 Codex 실행 환경에 따르며, 직접 API에서 같은 모델 이름을 사용할 수 있다고 보장하지 않습니다.

```sh
python -m pip install -r requirements.txt
python -m support_program_similarity.generative --corpus /data/programs.json --output /runs/new-gpt-run
```

기본값은 `--model gpt-6.1-sol --effort low --top-k 30 --timeout 2400`입니다. `--timeout`은 각 시도에 적용하는 초 단위 제한입니다. PATH에서 CLI를 찾을 수 없으면 `--codex-executable`로 실행 파일을 지정할 수 있습니다. 모델·인증·전송 오류가 발생하면 실패로 종료하며 다른 모델로 자동 대체하지 않습니다.

명령을 실행하면 **준비한 질의·후보 본문과 선택적 이름이 모델 서비스로 전송됩니다.** 모델 입력에는 순차 별칭과 제외 후보만 덧붙이고, 원래 ID는 로컬 대응표에 보존합니다. 원형 재현에는 동결된 질의·후보 입력 순서와 제외 목록도 보존해야 하며, 입력 순서가 바뀌면 별칭과 프롬프트가 달라져 동일 결과를 보장하지 않습니다. 모델 요청은 허용된 과제 필드로 구성되며 도구·웹 검색·이전 대화 연결을 사용하지 않습니다. 입력의 정답 파일을 읽지 않으며, JSON의 추가 필드를 모델에 전달하지 않습니다. 모든 질의와 후보 본문을 한 과제로 전달하고 본문이나 토큰을 잘라 맞추지 않으므로, 서비스의 요청·컨텍스트 한도를 넘는 입력은 실패할 수 있습니다.

각 질의의 서로 다른 허용 후보 30개와 상위 5개 후보의 인용 근거를 검사합니다. 인용은 질의·후보 원문의 실제 부분 문자열이어야 합니다. 인용만 잘못된 경우 최대 두 번 해당 필드 수정을 요청하며, 순위 또는 다른 필드가 함께 바뀌면 실패합니다. 구조 오류도 실패로 처리합니다. `--top-k`로 반환 순위 수를 정하며 근거 수는 `min(5, top_k)`입니다. 기본값 30을 바꾸면 위 성적과 같은 설정이 아닙니다.

출력에는 `rankings.json`, `blind_predictions.json`, `id_mapping.json`, 실행 해시·상태가 있는 `manifest.json`과 시도별 산출물이 생깁니다. 이 파일들은 실제 ID·본문 인용·실행 기록을 포함할 수 있으므로 저장소 밖에 보관합니다. 출력 폴더가 이미 있으면 덮어쓰지 않고 종료합니다. 동일 설정을 다시 실행해도 저장된 두 반복과 완전히 같은 순위나 수치가 보장되는 것은 아닙니다.

### 역사적 기준선: 로컬 Qwen 검색·재순위화

로컬 모델 스냅샷 두 개와 충분한 메모리가 필요합니다. 모델 다운로드와 가중치는 포함하지 않습니다. 기존 검색 진입점의 추론 동작은 유지했습니다.

```sh
python -m pip install -r requirements-inference.txt
python -m support_program_similarity.retrieval --corpus /data/programs.json --model /models/Qwen3-Embedding-8B --reranker /models/Qwen3-Reranker-0.6B --output /runs/new-qwen-run
```

원문 문자를 보존하면서 최대 4096 토큰 단위로 입력을 나눠 정규화 임베딩을 만들고, 토큰 수로 가중 평균한 뒤 다시 L2 정규화합니다. 질의에만 검색 지시문을 붙입니다. 코사인 상위 20개는 Qwen Reranker의 yes/no 로짓 점수로 재정렬하고 나머지 순위는 유지합니다. reranker 입력이 32768 토큰을 넘으면 오류로 종료합니다. 출력 폴더가 이미 존재해도 덮어쓰지 않고 종료합니다.

권장 reranker 스냅샷은 Qwen/Qwen3-Reranker-0.6B의 e61197ed45024b0ed8a2d74b80b4d909f1255473입니다. 실행 환경 참고 버전은 NumPy 2.2.6, PyTorch 2.8.0+cu128, Transformers 4.57.1, Sentence Transformers 5.1.2입니다. GPU·라이브러리·가중치 변경 시 동일 수치를 보장하지 않습니다.

과거 게시 검토에서는 토큰 디코딩으로 4개 문서의 문자가 달라지는 문제를 수정했습니다. 원문 위치 기반 분할로 153개 원문 보존을 확인하고 당시 4개 문서만 GPU 재계산했습니다. 3개 질의의 일부 순서는 바뀌었으나 지표와 재순위화 대상 집합은 같았습니다. 이번 갱신은 그 저장 산출물을 재사용한 오프라인 확인입니다. 기존 7개 구성 비교·입력 해시·Unicode 보존 검증은 선정 기록의 `historical_baseline`에 보존합니다.

## 오프라인 평가

추론 프로세스는 정답 파일을 읽지 않습니다. 아래 평가 명령은 별도로 실행합니다. 파일 접근 격리를 강제하는 OS 샌드박스는 이 코드에 포함되어 있지 않습니다.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m support_program_similarity --rankings examples/rankings.synthetic.json --positives examples/positives.synthetic.json --k 3
```

평가기 입력 두 파일은 각각 query_id -> candidate_id 목록 JSON입니다. AP 분모는 누락된 정답을 포함한 전체 알려진 정답 수입니다. MAP@K, MRR@K, 질의별 Recall@K의 매크로 평균을 계산합니다. all_positive_min_k는 모든 정답이 K 안에 있을 때 필요한 최대 순위이고, 하나라도 빠지면 null입니다. 정답이 없는 질의는 별도 평가가 필요하며 이 평가기는 오류로 처리합니다. 미판정 후보를 확정 음성으로 해석해서는 안 됩니다.

## 공개 범위

이 저장소는 준비된 사업 본문 이후의 검색·평가 단계입니다. 원본 파싱·청킹 및 기존 실험 전체를 이관한 상태는 아닙니다. 원본 HWP/HWPX/HPWX/PDF/Excel 등 문서, 실제 코퍼스·정답·실버셋, 모델, 벡터, 실행 로그는 외부에 보관합니다. 예제는 합성 ID만 사용합니다.

`python tools/check_publish.py`는 Git index의 실제 blob을 검사합니다. 허용된 소스 경로·확장자와 명시적으로 검토된 합성·선정 JSON만 통과시키며, 원본 문서 확장자, 이름을 바꾼 PDF·Office/ZIP 파일의 서명, 바이너리 제어 문자, 비밀키 패턴 및 개인 PC 경로를 차단합니다. `.gitignore`도 원본 문서와 내보낸 텍스트·데이터를 제외합니다. 정상적인 코드나 Markdown에 원문을 붙여 넣은 경우까지 자동으로 판별할 수는 없으므로 전체 변경 내용의 수동 검토가 필요합니다.

게시 전에는 검토한 파일만 명시적으로 스테이징하고 다음 순서로 검사합니다. `--base-ref`는 원격 기준 커밋부터 현재 HEAD까지 모든 새 커밋의 트리를 확인하므로, 중간 커밋에서 추가했다가 삭제한 원본 문서도 차단합니다.

```sh
git fetch origin main
python -m unittest discover -s tests -v
python tools/check_publish.py
git diff --cached --check
git diff --cached
# 검토한 변경을 커밋한 후, push 직전에 실행
python tools/check_publish.py --base-ref origin/main
git push origin main
```

로컬 원본 문서·실험 폴더는 게시 대상이 아닙니다. 전체 작업 폴더를 일괄 스테이징하거나 강제로 추가하지 마세요.

선정 근거, 반복별 재계산 지표, 원형 실행 코드·입력·산출물의 추상 이름별 SHA-256은 [release/selection.json](release/selection.json)에 기록합니다. 채택한 생성형 실행 코드와 기존 Qwen 검색 코드는 로컬 실험에서 이관했으며, 개인 PC 절대 경로와 정답 로딩을 추론 코드에서 제거했습니다. 원본 문서·실제 입력·정답은 이관하지 않았고, 평가는 별도 명령으로 실행합니다.
